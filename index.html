FAQ

Common questions, direct answers

What's your development process?

I start with understanding the problem deeply — user research, technical constraints, business goals. Then iterative prototyping: quick sketches → interactive prototype → production code with tests. Code reviews, CI/CD, and monitoring close the loop. I believe in shipping small, learning fast.

Which technologies do you specialize in?

Core: React/Next.js, TypeScript, Node.js, PostgreSQL. 3D: Three.js, React Three Fiber, WebGL shaders, GSAP. Infrastructure: Vercel, AWS, Docker, GitHub Actions. Testing: Vitest, Playwright, Testing Library. Currently exploring: Rust/WASM, WebGPU, local-first software.

Do you take on freelance or contract work?

Selectively. I prefer longer engagements (3+ months) where I can own a significant piece of architecture. Rate starts at $150/hr or project-based. Reach out with project scope, timeline, and team context — I'll respond within 48 hours.

How do you approach performance optimization?

Measure first, optimize second. Core Web Vitals as baseline. Bundle analysis, React Profiler, Chrome DevTools Performance tab. Techniques: code splitting, virtualization, memoization, streaming SSR, edge caching, image optimization, font subsetting. 3D: LOD, frustum culling, instancing, texture compression.

What's your stance on accessibility?

Non-negotiable. WCAG 2.1 AA minimum. Semantic HTML, keyboard navigation, focus management, ARIA only when necessary, color contrast, reduced motion, screen reader testing. Accessibility is not a checklist — it's how you build for everyone from day one.

How do you stay current with the ecosystem?

Source-first: read RFCs, follow core team members, contribute to OSS. Newsletters: Bytes.dev, TLDR, React Status. Conferences: React Conf, JSConf, RenderATL (speaker 2023). Side projects force learning — that's where Chronos and Voxel came from. I learn by building.
